# ARCHITECTURE.md — ReconAgent

## 1. Architecture

```
┌─────────────────────┐     ┌──────────────────────┐
│ gateway_settlements  │     │  internal_ledger      │
│ .json (synthetic)    │     │  .json (synthetic)    │
└──────────┬───────────┘     └──────────┬────────────┘
           └───────────┬────────────────┘
                        ▼
              ┌───────────────────┐
              │  Layer 1: Exact    │  ref/UTR + amount
              │  match (JS, det.)  │  within tolerance
              └─────────┬──────────┘
                        ▼ (unmatched only)
              ┌───────────────────┐
              │ Layer 2: Fuzzy     │  amount + date window
              │ match (JS, det.)   │  + string-similarity
              └─────────┬──────────┘
                        ▼ (still ambiguous)
              ┌───────────────────┐
              │ Layer 3: AI        │  Claude API, strict JSON,
              │ escalation (bounded)│  capped calls, try/catch
              └─────────┬──────────┘
                        ▼
              ┌───────────────────┐
              │  Audit log +       │  match rate, precision,
              │  exceptions list   │  recall, per-record trail
              └─────────┬──────────┘
                        ▼
              ┌───────────────────┐
              │  Express API +     │  vanilla HTML/JS dashboard
              │  static dashboard  │  (no build step)
              └───────────────────┘
```

### Design principle behind the layering
Each layer only ever sees what the previous layer failed to resolve. This is deliberate:
- It keeps the AI layer small, cheap, and bounded — a direct answer to "AI Judgment."
- It makes the audit trail meaningful: you can always say *which* layer made a decision and why.
- It means AI failure (bad response, timeout, malformed JSON) only ever degrades a small subset of records to "unresolved," never the whole pipeline.

## 3. Tech Stack

| Layer | Choice | Why |
|---|---|---|
| Backend | Node.js + Express | Fast to scaffold, zero build step, matches strongest stack |
| Frontend | Vanilla HTML/CSS/JS | No React/Vite/bundler — nothing to break under demo pressure, fastest to ship in <24h |
| Fuzzy matching | `string-similarity` (npm) | Lightweight, no ML model needed, deterministic and explainable |
| AI escalation | `@anthropic-ai/sdk`, model `claude-sonnet-4-6` | Structured JSON output, only invoked for genuinely ambiguous cases |
| Storage | Flat JSON files | No DB setup overhead; data is small (60-80 records) and disposable |
| Testing | Node's built-in `node:test` or `jest` (pick one, keep light) | Unit tests only for the deterministic matchers — cheapest confidence per hour spent |
| Dev tooling | `nodemon` (dev dependency only) | Fast iteration, not shipped as a runtime dependency |

No database, no auth library, no frontend framework, no ORM — every dependency above earns its place or it doesn't go in `package.json`.
